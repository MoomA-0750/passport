# 運用に入ると効いてくる機能の実装計画（2026-09-16）

一般的なパスワードマネージャーにあって Passport に無いもののうち、
「運用に入ると効いてくるもの」を実装する。本人の依頼。

前回は対話しながら一気に作ってレビューのタイミングが無かったので、
**今回は着手前にマイルストーンとレビューを置く場所を決める。**

## 本人が決めたこと

| 論点 | 決定 |
|---|---|
| SSH エージェントで秘密鍵をどこで使うか | **端末に鍵を持ってくる。** エージェント起動時に鍵を取得してメモリに持ち、手元で署名する。Passport が落ちていても ssh できる。鍵が端末のメモリに載り、個々の署名は監査ログに残らないことを受け入れる |
| CLI の範囲 | **人用と自動化用の両方。** 人は対話ログインで短命トークン。cron やデプロイ用に、Vault を限定・読み取り専用・期限付きの自動化トークンを発行できる |

## マイルストーン

依存の向き: グループが権限の土台になり、ほかの機能はその権限で動く。

| # | 内容 | レビュー |
|---|---|---|
| M1 | **グループ**（共有をグループ単位で） | **Fable 審査点** |
| M2 | **ログイン中の端末の管理**、**自分の履歴** | inner gate（自分で見直し + テスト） |
| M3 | **点検**（弱い・使い回し・古い・期限切れ）と**棚卸しのリマインド** | **Fable 審査点** |
| M4 | **CLI** と**自動化トークン** | **Fable 審査点** |
| M5 | **SSH エージェント** | **Fable 審査点** |
| — | 全体 | **outer gate**（独立した複数観点のレビュー + Codex の読み取り専用レビュー） |

各マイルストーンの終わりにテストを通して commit・push し、Vault に進捗を残す。
途中で止まっても、次のマイルストーンから再開できるようにする。

### Fable 審査点の理由

4条件（やり直せない・安全境界・後工程が依存・テストで拾いにくい）で判定した。差分の大きさでは決めない。

- **M1 グループ**: 安全境界（実効権限の計算そのものを変える）、後工程が依存（M2〜M4 がこの権限で動く）
- **M3 点検**: 安全境界（使い回しを見つけるにはサーバーが全件を復号して比べる。結果として何を見せてよいかの線引き）、テストで拾いにくい（漏れは「見えてはいけないものが見えた」ことでしか分からない）
- **M4 自動化トークン**: 安全境界（新しい認証経路）、やり直せない（漏れたトークンで取られた秘密は戻らない）
- **M5 SSH エージェント**: 安全境界（秘密鍵が端末のメモリに出る）、やり直せない、テストで拾いにくい（エージェントのプロトコル実装）

M2 は情報を見せる範囲の判断があるが小さいので、Fable は呼ばない。

## 設計

### M1 グループ

- 管理者がグループを作り、メンバーを入れる（`data/groups/<id>.json`）
- Vault の共有にグループを足せる（`vault.json` の `groups: [{ groupId, role }]`）
- **実効ロール = 個人に付いたロールと、所属グループのロールのうち一番強いもの**
- 権限の判定は今と同じ `vaults.requireAccess` → `roleOf` の1か所に閉じる。ほかの場所で判定を作らない
- **最後の owner の保護は、個人に付いた owner だけを数える。** グループは空にできるので、グループの owner しかいない Vault は誰も管理できなくなりうる
- 使われているグループは消せない（使われている Vault を示す）
- 監査ログ: グループの作成・変更・削除、メンバーの出入り、Vault へのグループの追加・変更・削除

### M2 ログイン中の端末 / 自分の履歴

**ログイン中の端末**
- 自分のセッションの一覧（ログイン時刻・最後の操作・接続元・ブラウザ・画面／拡張／CLI の別・今使っているもの）
- 1つずつ切る、自分以外を全部切る
- **セッション ID そのものは返さない。** 鍵付きハッシュの短い表示用 ID で指す

**自分の履歴**
- 自分が行った操作と、自分のアカウントへのログイン試行
- **自分が owner の Vault** で、ほかの人が秘密を見た・コピーした・入力した・変えた記録
- editor / viewer には、共有 Vault でのほかの人の操作は見せない（見せてよい範囲を owner に限る）

### M3 点検とリマインド

- アイテムに**ローテーション周期**（90 / 180 / 365 日など）と**有効期限**（証明書・ライセンス用）を設定できる
- 点検の画面で出すもの:
  - **弱い**パスワード
  - **使い回し**（同じパスワードを使っているアイテムの組）
  - **古い**パスワード（周期の設定が無いものは 365 日）
  - **期限切れ・期限間近**（周期または有効期限から 30 日以内）
- **自分が見られる Vault の中だけで比べ、結果もその中だけ。** 見られない Vault のアイテムとの一致は出さない
- **値は返さない。** 弱い・使い回しの判定にはサーバーが復号するが、返すのはアイテムの組とタイトルだけ
- 比べるための指紋をファイルに**保存しない**（盗まれた data/ に「このアイテムは弱い」「この2つは同じ」という手がかりを残さない）。点検のたびにメモリの中で計算して捨てる
- 監査ログには点検を1行（件数だけ）。アイテムごとの「閲覧」は積まない（人が中身を見たわけではないため）
- ナビゲーションに、期限切れ・期限間近の件数のバッジ（こちらは復号不要）

### M4 CLI と自動化トークン

**CLI（`bin/passport`、Node 標準のみ）**
- `passport login` / `logout` / `whoami`
- `passport vaults` / `ls <Vault>`
- `passport read "<Vault>/<アイテム>/<フィールド>"` — スクリプトから `$(passport read ...)` で使う
- `passport totp "<Vault>/<アイテム>"`
- 自己署名の証明書は `--ca` か設定の `caFile` で指定（Node の fetch は `ca` を渡せないので https モジュールで話す）
- 人用のセッションは `~/.config/passport/` に 0600 で置く

**自動化トークン**
- 形式 `pp_<ID>_<秘密>`。**サーバーには鍵付きハッシュだけを置く**（一度だけ表示）
- **Vault を限定・読み取り専用・期限付き**（期限は必須、最長 365 日）
- 発行できるのは、対象の Vault すべての owner。管理者は一覧と失効ができる
- トークンでできるのは、対象 Vault の一覧と秘密の取り出しだけ。書き込み・管理 API・ほかの Vault は不可
- 使うたびに監査ログに残す（実行者は「トークン名」）
- CSRF の免除は、トークンが実在して有効なときだけ（セッションの Bearer と同じ考え方）

### M5 SSH エージェント

- `passport ssh-agent` が Unix ソケットで OpenSSH のエージェントプロトコルを話す。
  `eval "$(passport ssh-agent)"` で `SSH_AUTH_SOCK` を設定する
- 起動時に、自分が見られる SSH 鍵を取得してメモリに持つ（取得は鍵ごとに監査ログに残る）
- 署名は手元で行う（Node 標準の `crypto.sign`）。ed25519 と RSA（rsa-sha2-256 / 512）
- **パスフレーズ付きの OpenSSH 形式の鍵は読めない**（bcrypt_pbkdf を書かない方針）。読み飛ばして知らせる
- **寿命**（既定 8 時間、`--lifetime`）を過ぎたら鍵を捨てて終了する
- ソケットは 0600、ディレクトリは 0700
- 個々の署名は監査ログに残らない（本人の決定として受け入れる）
